## 1. 我われはなぜここにいるのか

- **いちばんの目的（Q1）**：**AI-SCRUM のプロセス（ORIGIN・OPTION・TEAM）を、実際のプロダクトで試す**。
- そのため、早いスプリントから「PBI → TASK → PR → CI → プレビュー → 実機確認 → AC → レビュー → レトロスペクティブ」をひと回りさせ、プロセスの改善点を見つけることにも価値をおく。
- プロダクトとしての価値：すき間時間に 1 プレイ 3 分前後で終わり、TOP10 に名前を残すためにくり返し遊べるゲームにする。
- 遊ぶ人：オーナー。オーナー以外に見てもらう予定は今はない。

## 2. エレベーターピッチ（Q2：遊ぶ人の目線）

すき間時間に手応えのある 1 プレイがほしい人向けの、『最終防衛線ミニ』は 1 面完結の防衛シューティングです。これは降ってくるミサイルを爆風の連鎖でまとめて落とす気持ちよさを 3 分で味わえ、長く続くアーケードゲームとは違って、1 回で終わり TOP10 に名前を刻めるところまでが備わっている。

## 3. パッケージデザイン

- **名前**：最終防衛線ミニ
- **キャッチコピー**：「3 分間、街を守り抜け。」
- **うれしいこと 3 つ**
  1. 1 面完結。1 プレイ 3 分前後で、すき間時間に終わる
  2. 1 発の迎撃で何発もまとめて落とす、誘爆の連鎖が気持ちいい
  3. TOP10 だけが残る厳しいランキング。入れば名前が光る
- **見た目の方向**：黒い夜空と独自の配色のドット絵。原作の黄色い地形・青い都市・赤い八角形の終了画面は使わない。細部は画面の設計（GUI）で PO が決める。

## 6. 解決案を描く

`docs/spec/ARCHITECTURE-TEMPLATE.md`（銀河戦争ミニの構成）を使う。初版の設計は `LLM-SA-0001`（システム構成）と `LLM-TS-0001`（技術スタック）。

```
 ┌──────────── 遊ぶ人の端末（PC / iPhone） ────────────┐
 │  ブラウザ                                             │
 │  画面（Canvas）・入力（キー／マウス／タッチ）          │
 │        ↓ 入力              ↑ 状態                     │
 │  ゲームのロジック（状態と入力 → 次の状態。乱数は種）    │
 │        ↓ 結果                                         │
 │  ランキング（TOP10）→ localStorage                     │
 └─────────────────────────────────────────────────────┘
          ↑ 読み込み（初回のあとはオフラインでも動く：PWA）
 ┌──────────── GitHub ────────────┐
 │ main にマージ → /preview/ に公開 │  ← プレビュー
 │ リリースのタグ → / に公開        │  ← 本番
 │ PR ごとに CI（テスト）          │
 └────────────────────────────────┘
```

テンプレートと違うところ：公開先を 2 つにする／音（audio 層）は LLM-PG-0002 の LLM-PBI-0014 で作る（Web Audio の合成）／記録の書き出し・読み込みは作らない（2026-11-20 に「やらない」へ）。

### 7a. 仕様書のあいまいな点（各 PBI のリファインメントで決める）

1. 敵の総数・ウェーブの数・1 プレイの長さ（案：6〜8 ウェーブ、約 5 分 → 2026-11-13 の PO の決定で 5 ウェーブ、守り切って 2 分半〜3 分半）→ LLM-PBI-0004・0011
2. 「全拠点の弾薬が尽きて着弾を阻止できなくなった時点でゲームオーバー」と「最終弾頭が消えた時点で都市が残ればクリア」が重なる場面 → LLM-PBI-0004
3. 敵が基地に当たったときの扱い → LLM-PBI-0003
4. 10 位と同点のスコアはランクインしない、でよいか（§5.1 と §5.3）→ LLM-PBI-0006
5. ネームエントリーをスマートフォンでどう操作するか → LLM-PBI-0007
6. スマートフォンの照準と発射の操作 → LLM-PBI-0002（試作で決める）

## 8. 期間を見極める

- プロダクトゴール（LLM-PG-0001）に入る PBI は **11 個**（ほかに次のゴールの候補が 2 個、「あとで決める」が 5 個。2026-11-18 に「あとで決める」のうち 2 個〔ゲームパッド・難易度の選択〕を PO が削除し、3 個になった）。
- 実績（スプリント 01・02）：1 スプリントに完成した PBI は 1 つずつ。作業はどちらも初日（約 3〜3.5 時間）で終わった。
- 見込み：**プロダクトゴールまで、あと 9 スプリント（約 9 週間）**。残りの 9 PBI を、今の実績（1 スプリントに 1 PBI）で数えたもの（PO の決定、2026-11-04 のスプリント 02 のレビュー）。
- **最初に PC で 1 面を最後まで遊べる**のは、LLM-PBI-0003〜0005 がそろう**スプリント 05 の終わり**の見込み。
- 1 スプリントに入れる PBI を増やせば短くなる（入れる量はプランニングで PO が決める）。
- **結果**：LLM-PG-0001 は 13 PBI・スプリント 01〜12 で、2026-11-18 に達成した（1 スプリントに 1 PBI、スプリント 06 だけ 2 PBI）。
- **次のゴール（LLM-PG-0002 v1.1、2026-11-19）**：爆撃機と衛星（LLM-PBI-0009、M）→ 効果音・BGM（LLM-PBI-0014）の 2 PBI。見込みは 2〜3 スプリント。
- **結果**：LLM-PG-0002 は 3 PBI（0021 を足した）・スプリント 13〜15 で、2026-11-19 に v1.1.0 で達成した。
- **次のゴール（LLM-PG-0003、2026-11-19）**：一時停止（LLM-PBI-0016、S）の 1 PBI。見込みは 1 スプリント。
- **作り直し（LLM-PG-0003 v1.1、2026-11-20）**：一時停止（LLM-PBI-0016、S）→ ランキングのデータを消す（LLM-PBI-0022、S）の 2 PBI。1 スプリントに 1 PBI（別々の PBI）で、見込みは 2 スプリント（スプリント 16・17）。「あとで決める」は 0 個になった。
- **結果**：LLM-PG-0003 は 2 PBI（0016・0022）・スプリント 16〜17 で、2026-11-20 に v1.2.0 で達成した（見込みどおり 2 スプリント）。PO の決定で次のゴールは置かず、ここで開発を区切った。
- **次のゴール（LLM-PG-0004、2026-11-20）**：区切りのあと、PO がタイトル画面の BGM（LLM-PBI-0023、S）を依頼した。1 PBI で、見込みは 1 スプリント（スプリント 18）。そろったら v1.3.0 で本番に公開する。
