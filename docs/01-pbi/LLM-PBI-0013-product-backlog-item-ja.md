# LLM-PBI-0013 README と権利・クレジットの表記がある

## ストーリー

このゲームを見つけて遊ぶ人として、ゲームの中で作った人と使った道具の権利を見たい。また、リポジトリを見る人として、README で遊び方・動作を確かめた端末・気をつけることを読みたい。それは、だれが作ったかが分かり、安心して遊べるから。

## 受け入れ条件

| 確認 ID | 条件 |
| :--- | :--- |
| LLM-TC-0013-01 | リポジトリの一番上に README があり、ゲームの名前と紹介・遊ぶ場所（本番とプレビューの URL）・遊び方（PC・iPhone）・動作を確かめた端末（PC・iPhone。Android は確かめていない）・iPhone でランキングが消えることがあること（ホーム画面に置けば消えにくい）・新しい版の更新と起動の復旧・クレジット・使った道具の権利の表記が書いてある。原作の名前は書かない。ライセンスの節は置かない（PO の決定） |
| LLM-TC-0013-02 | タイトル画面にだけ「クレジット」ボタンがある（TOP10・プレイ中・終わり・名前の入力には出ない）。ボタンを触る／クリックするとクレジット画面が開き、ゲームは始まらない。ボタンの外を触る／押すのは今までどおり（ゲームが始まる）。ボタンは一番小さい iPhone SE 第 3 世代でも 44 ポイント以上 |
| LLM-TC-0013-03 | クレジット画面に、上から PRODUCER・DIRECTOR・GAME DESIGNER（つくだ よしはる）、GRAPHIC DESIGNER・SOUND CREATOR・PROGRAMMER（CLAUDE CODE）の 6 つと、使った道具とその権利の表記が出る。入りきらないときは上下に動かして読める。「BACK」ボタンか Esc キーでタイトルに戻る。それ以外のキー・触る操作ではゲームは始まらない。更新の帯は出さない |
| LLM-TC-0013-04 | 公開する版（dist）に入っている外の道具（npm のパッケージ）は、すべてクレジット画面と README に名前・著作権・ライセンスの文が載っている（MIT の条件） |
| LLM-TC-0013-05 | iPhone 11 の Safari でプレビューを開き、タイトルの「クレジット」→ 上下に動かして最後まで読める → 「BACK」でタイトル → 1 プレイして fps 55 以上 |

## 画面

LLM-GUI-0003 §7（クレジットのボタンと画面。v1.3）。クレジット画面は、更新の帯と同じくブラウザの文字（ゴシック）の HTML で、ゲーム画面の上に重ねる（名前がひらがなで、自前のドットの文字は英数字だけのため）。

## 範囲に入れないもの

- ライセンスの文（`LICENSE`）。PO の決定（2026-11-18）で書かない。このゲーム自体の権利は作者が持つ
- 本番への公開（リリースのタグ）。本番に公開するかはスプリントレビューで PO が決める
- 効果音・BGM（LLM-PBI-0014）。SOUND CREATOR は PO の決定でクレジットに載せる
- TOP10 の画面からのクレジットの入り口

## メモ

- PO が置いたクレジットの例：`docs/screenshot/クレジット（例）.PNG`（Git には入れない）
- 2026-11-18 の PO の決定（スプリント 12 のプランニング）：範囲は「README＋ゲーム内クレジット」、ライセンスは「記載しない」、クレジットは「例のとおり 6 つすべて」
- 外の道具の権利：dist には Vite・vite-plugin-pwa・Workbox（`workbox-window`、SW の中の `workbox-*`）のコードが入る見込み（どれも MIT。著作権とライセンスの文を添えるのが条件）。どれが入るかは TASK で dist を調べて決め、クレジット・README・check-dist の 3 か所をそろえる
- 開発者の決め：クレジットの中身（役割・名前・道具・ライセンスの文）は 1 つのデータ（`src/app/credits.ts`）にまとめ、画面はそこから作る。check-dist は dist にライセンスの文が入っていることを確かめる
- 大きさ：M（画面 1 つ＋README。2 TASK）。最後の実機確認は、コードの TASK のマージで公開される版で行う（`pages.yml` は `docs/**`・`**/*.md` だけのマージでは走らない。案 15）
