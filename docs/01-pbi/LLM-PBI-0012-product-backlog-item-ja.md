# LLM-PBI-0012 ホーム画面のアプリが「更新」ボタンで新しい版になり、起動に失敗しても戻せる

## ストーリー

iPhone のホーム画面で遊ぶ人として、新しい版が出たら自分の好きなときに更新したい。また、起動に失敗しても自分で戻したい。それは、遊んでいる最中に壊れず、困ったときも続けられるから。

## 受け入れ条件

| 確認 ID | 条件 |
| :--- | :--- |
| LLM-TC-0012-01 | 新しい版を見つけても、勝手に切り替わらない。タイトルと TOP10 の画面にだけ、画面の上に「新しい版があります」と「更新」ボタンの帯が出る。プレイ中・終わりの表示・名前の入力の画面には出ない（プレイ中に見つけたら、次にタイトルか TOP10 に来たときに出る） |
| LLM-TC-0012-02 | 「更新」ボタンを押すと新しい版に切り替わって読み込み直し、右下の番号が新しくなる。帯を押してもゲームは始まらない（帯の外を触る／押すのは今までどおり）。ボタンは一番小さい iPhone SE 第 3 世代でも 44 ポイント以上 |
| LLM-TC-0012-03 | ホーム画面のアプリを前に戻して見えるようになったとき（オンラインのとき）にも、新しい版を探す |
| LLM-TC-0012-04 | アプリの本体が 8 秒たっても画面を出せないときは、復旧の画面（「再読み込み」「キャッシュを消して再読み込み」）が出る。後者は自分のチャンネルの SW の登録とキャッシュだけを消し、ランキング（localStorage）は消さない。ふだんの起動では復旧の画面は出ない |
| LLM-TC-0012-05 | 本番とプレビューを取り違えない：プレビューの更新・復旧は本番の SW とキャッシュに触れず、本番の SW はプレビューのページを扱わない。dist に `boot.js` があり、アプリ本体より先に読まれる |
| LLM-TC-0012-06 | iPhone 11 のホーム画面に置いたプレビューで、新しい版が公開されたあと前に戻すと帯が出て、「更新」で右下の番号が新しくなる。ランキングは残っている（右下の番号が最後のコードの PR のマージと同じ → 次のマージのあとに確かめる） |

## メモ

- 2026-11-18 の PO の決定（スプリント 11 のプランニング）：入る量は「0012 だけ」、更新ボタンは「B 上の帯（日本語）」
- 今あるもの：vite-plugin-pwa の `registerType: 'prompt'`・`injectRegister: false`、`src/app/pwa.ts` で `registerSW` を自分で呼ぶ（スプリント 01 の骨組み）
- 開発者の決め（テンプレート §5.9 の作り）：
  - `onNeedRefresh` で「待っている版がある」を覚え、タイトル・TOP10 の画面のときだけ帯を出す。押したら `updateSW(true)`
  - 登録の直後と `visibilitychange`（見えたとき・`navigator.onLine`）に `registration.update()`
  - `public/boot.js`（ES5 の普通のスクリプト）を `index.html` でアプリ本体より先に読み、8 秒のタイマー。アプリが最初の画面を描いたら `window.__lastLineMiniBooted()` で止める。消すキャッシュは `<app-id>` で始まるものだけ（本番 `last-line-mini`・プレビュー `last-line-mini-preview`。本番がプレビューのキャッシュを消さないよう、名前の続きまで見る）
  - `?debug=1` の `simulateUpdate()` で帯を出せるようにし、E2E で確かめる（テンプレート §5.10）
  - 帯を押したときは、`pointerdown` がゲームの「触る／押す」に届かないよう止める
- 大きさ：M（1〜2 TASK）。最後の実機確認は「次のマージで新しい版が出る」ことが要るので、記録の PR などのマージのあとに行う
