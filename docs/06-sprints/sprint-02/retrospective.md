## 言葉の表

| 言葉 | 意味 |
| :--- | :--- |
| PBI | 作りたいもの 1 つ（プロダクトバックログの 1 行） |
| TASK | PBI を作るための作業 1 つ。1 つの TASK を 1 つの PR にする |
| PR | 変更を本流（main）に入れてよいか確かめてもらう申請 |
| CI | PR のたびに自動で動く検査（lint・テスト・build） |
| フック | Git の操作（コミットなど）の前に自動で動く点検 |
| メトリクス | チームの状態を確かめるために計る数字 |
| リードタイム | 始まりから届くまでの長さ |

- **つまずき 1**：作業ブランチを切らずに、手元の main にコミットした（TASK-0010）。→ なぜ：マージのあと main に戻り、そのまま作業を始めた。→ どうしたか：コミットを作業ブランチに移し、手元の main を戻した（GitHub には送っていない）。

- **つまずき 4**：実機確認の 1 回目で fps が出なかった。→ なぜ：Safari に前の版が残っていた（ホーム画面のアプリと Safari は版を別々にしまい、勝手には切り替わらない）。→ どうしたか：タブを閉じて開き直してもらった。実機確認の案内の最初に、右下の番号を確かめてもらう。

- PR を作ってからマージまでは 2〜7 分がほとんどで、PO の待ちで流れは止まっていない。流れを止めているのは、1 スプリントに入れる量の少なさと、PO が決めることの待ち（スプリント 01 の試作の返事など）。
